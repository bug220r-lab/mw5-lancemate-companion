# Preview deadline changes preserve conversation state

2026-09-22 — corrected project-local lifecycle behavior, **MOCK_ONLY** validation. No native model, editor, game, microphone or audio device was executed for this change.

The workbench's `preview_timing` action previously disposed its coordinator, constructed another and started the current mission ID again. This discarded coordinator clock/identity/deduplication memory even though the mission had not changed. A read-only inert-engine reproduction showed a concrete consequence: after the supplied clock regressed from 10,000 to 9,000, conversation returned `CLOCK_INVALID`; selecting the already-active 4,000 ms preview deadline then allowed a generated answer at 9,000 in the same `demo_1` mission. That reproduction wrote no files and started no workers; its output was reported to the supervising task, not saved as a native receipt.

An abort-ignoring injected generator also demonstrated loss of the coordinator's occupied slot: two promises could remain outstanding after reconstruction. This does **not** establish overlap in the real native adapter, which independently exposes `GENERATING` and rejects another `generationPromise`. A native-like fake with that busy state blocked the second workbench request. The existing workbench possession snapshot still rejected a possessed actor and retained human holds; no native wrong-recipient or override failure was demonstrated. Request/session/old pawn-claim histories were structurally lost, but the present workbench does not accept caller-selected request/session IDs or arbitrary binding updates that would reproduce those replay paths.

The coordinator now exposes `setTimeoutMs(value)`. It accepts only a primitive integer from 1 through the existing 10,000 ms maximum. Invalid values and disposed instances reject without changing settings or cancelling work. Every valid selection, including the same value, cancels pending previews with `PREVIEW_TIMING_CHANGED`, preserving the previous cancellation behavior. Future requests use the selected deadline, further bounded by request and fact expiry.

The same coordinator remains alive. Generated history stays explicitly unverified and possibly undelivered; changing a deadline neither deletes nor promotes it. Clock faults and time floors, actor generations/revocations, pawn ownership, request/session IDs, gates and the active generator slot remain intact. A cancelled generator retains that slot until its original promise settles; its late result cannot restore text/history or bypass queued ownership. `getState()` exposes the selected `timeoutMs` for inspection.

The server keeps its existing reply/audio/radio invalidation, updates the deadline in place and never reconstructs or restarts the conversation mission for this preference. The coordinator reference is now constant. Human-order policy state is untouched. The separate actual mission-reset path remains explicit. This follows the same state-preserving principle as the callsign update, while keeping history because timing does not change speaker identity.

Validation: **114/114 focused tests pass, MOCK_ONLY**, across two runs: 46 coordinator/timing/callsign checks and 68 existing server/browser conversation/playback checks. Nine new implementation cases cover the concrete same-mission clock regression, ignored abort ownership, retained history and deduplication, invalid/disposed updates, and selected/request/fact timeout limits. Existing audio cancellation checks still pass. The supervising task updated the prior history-reset assertion to compare the preserved nonempty history, retaining the rest of its coverage. The separately owned adversarial review is `research/PREVIEW_TIMING_REVIEW.md`.

This change does not alter the experimental projection, model configuration, prompt/output limits, four-second first-spoken target or native acceptance. The earlier fixtures, diagnostic receipts and preflight receipt remain unchanged and attributable to their recorded source hashes; any later native run needs a fresh source/preflight check. Full regression and final checkpoint are owned by the supervising task.
