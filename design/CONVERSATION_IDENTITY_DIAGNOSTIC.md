# Native speaker-identity diagnostic preparation

2026-09-22. **PREPARED; native inference NOT_PERFORMED.** This bounded text-only experiment tests the explicit identity projection introduced in [the context design](CONVERSATION_IDENTITY_CONTEXT.md). It uses the separately specified eight cases and acceptance criteria in [the independent evaluation](../research/CONVERSATION_IDENTITY_EVALUATION.md). It does not establish full conversation readiness, select a model or enable mission radio.

`scripts/Exercise-ConversationIdentity.mjs --check` imports the real coordinator and serializer, verifies the frozen fixture's exact SHA-256, and prepares all eight contexts without constructing or starting a native engine, reserving a result receipt, or checking current resource readiness. Import alone is inert. Only the exact argument `--run` selects future inference; there are no output-path, model, tuning or retry arguments.

For seven cases, preparation creates a fresh real coordinator, applies only the specified fixture callsign override, starts its exact three-actor synthetic binding set and submits its actual answer request. An inert injected generator captures the resulting frozen context. Fact data must survive exactly with the caller-assertion label and without the input `verified` flag. The placeholder response is never included in measured history. The eighth context intentionally omits actor binding. Expected meanings, forbidden claims and rationales are recorded in the receipt's fixture, never model input. The fixed capture clock is synthetic: passing these contexts later to a native model does not test live freshness or native identity.

The frozen input is `synthetic/conversation-identity-cases.json`, SHA-256 `4ffda0d912a22828bd34a3fbc91b616a60d9b1b510b89576b70bf2f1c01385b1`. Changing even whitespace refuses the experiment before native execution. Existing evidence is never overwritten. Future `--run` exclusively creates `research/QWEN4B_IDENTITY_DIAGNOSTIC.json` using `wx`, keeps its owned file handle for checkpoints, and refuses a repeat before constructing an engine. Preparation does not create that receipt.

The future run uses the already installed Qwen3-4B Q4_K_M with the pinned CPU llama.cpp runtime, four threads, compact 128/64 batches, disabled weight repacking, one native slot, 2,048 context tokens, 64 output tokens, 256 output characters, nonthinking mode and prompt caching. These are experiment-local settings, not a default change. A separate `Say OK.` primer may establish shared-prefix reuse; its output is discarded and never enters case history. Report startup and primer costs separately. No download, GPU offload, synthesis, playback, microphone, game/editor execution or command dispatch is part of the harness.

Admission requires 5 GiB available RAM and 10 GiB free disk. Available RAM is sampled every 250 ms; falling below 2 GiB or losing a valid RAM measurement cancels work. Each generation has a 10-second deadline, including calibration. The total work deadline is 233 seconds, followed by at most a seven-second cleanup wait. Startup and generation waits observe cancellation even if their underlying promises ignore it; later cases never start after a failure. Shutdown targets only the adapter-owned process. Failure to confirm its exit is `OWNED_PROCESS_STOP_UNCONFIRMED`, not success or permission to start another worker. These are reactive supervision attempts, not hard guarantees about OS memory allocation, filesystem completion or termination.

Before a future run, the supervising task must confirm that other native model/recognition workers are stopped and preserve the user's request to leave the unused editor closed. The harness verifies its own pinned model/runtime files through the existing adapter, but does not inventory or terminate unrelated applications. The 10 GiB disk reserve is measured at admission; this experiment downloads no artifacts or model caches. Its small receipt is the only new project result file.

The receipt includes the exact fixture, captured contexts, messages, source hashes, model/archive/runtime pins, configuration, output, native timing counters, resource observations and unperformed cases. Any timeout or error stops the run rather than retrying an answer. No answer is semantically scored by the harness. The existing adapter does not expose `finish_reason`; `TEXT_COMPLETE_DIAGNOSTIC_ONLY` means the adapter returned text, not proof that it ended naturally. Preserve `predicted_n`; a response at the 64-token cap needs conservative semantic review for possible truncation. Missing required meaning or a forbidden claim fails even if the response also contains a disclaimer.

The earlier twelve-case factual failures remain valid evidence. Eight successful identity answers would support only this narrow projection hypothesis, not four-second first-spoken latency, factual reliability, observed gameplay, personal style or release acceptance. Do not revise the frozen criteria after seeing outputs or characterize these stochastic cases as a reliability estimate.
