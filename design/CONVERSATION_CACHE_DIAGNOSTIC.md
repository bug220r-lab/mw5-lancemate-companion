# Single-slot prompt cache experiment

Prepared 2026-09-22. **PROPOSED local CPU diagnostic; native result NOT_PERFORMED.** The editor stays closed. No microphone, playback, TTS, game workload or external service participates.

The previous editor-closed 4B run processed only part of its first prompt before the ten-second response deadline. The adapter explicitly disabled prefix caching. The pinned llama.cpp source supports reusing identical prompt-prefix tokens while removing the divergent suffix; the [source review](../research/CONVERSATION_CACHE_SOURCE_REVIEW.md) records the exact version and limitations. Reusing the fixed grounding instructions is a testable latency hypothesis. It does not relax the grounding rules or establish a usable conversation model.

`scripts/Exercise-ConversationCache.mjs --check` prepares the unchanged twelve-case fixture and a separate calibration request; it does not start a worker, reserve a result file, or establish current resource readiness. Explicit `--run` exclusively reserves `research/QWEN4B_PROMPT_CACHE_DIAGNOSTIC.json`. An existing receipt refuses another run. Earlier grounding receipts remain unchanged.

The only inference change is opt-in `cache_prompt: true`. Model/runtime pins, CPU four threads, one slot, 2,048 context, 64 output tokens/256 characters, compact 128/64 batches, no repacking, sampling and all case prompts remain unchanged. Production/workbench caching stays disabled. Native secondary-cache allowance retains its source-documented default; it is a maximum allowance, not a measured allocation. The experiment does not assume caching costs zero memory.

Before the cases, one calibration request says `Say OK.` with persona `{id: 'calibration'}` and empty facts/history. Its identity is independent of the twelve test personas. The normal adapter renders the common rules and an empty persona object. Its output is kept only as a diagnostic record and discarded from every later prompt. It is never a verified fact, prior dialogue, spoken response or command. No special prompt-only endpoint or zero-token generation contract is used.

Each of the twelve cases then sends its complete, unchanged current messages. Reuse is only a native computation optimization, not an application memory mechanism. Capture optional bounded backend timing fields and log excerpts to distinguish reported prefix reuse from an unverified cache assumption. These metrics describe the native server's claims; they are not independently measured token counts or proof that a response is correct.

Admission needs 5 GiB available RAM and 10 GiB free disk. A 250 ms monitor aborts below 2 GiB available RAM. Calibration and every response have the same ten-second deadline; all work has a 233-second budget plus seven-second cleanup budget. Failure stops the experiment, records the remaining cases NOT_PERFORMED, and confirms shutdown of the single owned worker. Sampling is reactive, not a reservation. Root confirms no competing editor/model worker before launch. Stop does not affect unrelated processes.

Report startup, calibration, each warm request and total time separately. Include calibration in total workload; never compare warm text alone with cold or first-spoken acceptance. The four-second spoken-response target remains unchanged. A single stochastic run is not a controlled speed comparison. An independent reviewer evaluates any completed answers against the existing semantic requirements; no model/default/capability promotion follows automatically. On failure, preserve the result and do not rerun the same configuration.

## Executed result

The supervising task subsequently ran this experiment once after 706 offline checks passed, a fresh 5.54 GiB available-RAM check and confirmation that no editor or other model worker was running. The [immutable receipt](../research/QWEN4B_PROMPT_CACHE_DIAGNOSTIC.json) records **12/12 completed texts**, **6.834 seconds startup**, **5.559 seconds calibration** (`OK.`), and **81.162 seconds total**. All twelve measured requests contain backend-reported prefix reuse, between 84 and 135 cached tokens. Full texts took **3.153–8.242 seconds**, median **6.063 seconds**; ten exceeded four seconds even before any speech synthesis. No first-audible timing was measured.

Minimum sampled available RAM was **2.901 GiB**. There was no resource/deadline stop, all owned-process shutdown checks passed, and the editor remained closed. Every recorded source hash and all twelve complete supplied prompts matched the prepared artifacts when checked afterward. Warm-up and calibration are included in the total. The earlier timeout remains preserved and is not a controlled performance baseline for this changed configuration.

Several completed texts invent action completion, mission victory, identity or verification from untrusted dialogue. The [independent semantic review](../research/QWEN4B_PROMPT_CACHE_RESULT_REVIEW.md) records **six semantic passes and six failures** across the twelve completed answers. **This candidate is not accepted for factual mission dialogue.** Runtime completion and reported cache hits do not repair its grounding failures. Keep the workbench defaults unchanged, preserve these outputs, and do not rerun the same configuration or label these now-inspected cases an unseen holdout in later prompt-tuning work.
