# Callsign preferences in conversation previews

2026-09-22 — project-local correction; validation is **MOCK_ONLY**. Native conversation quality, real browser/audio-device behavior and gameplay acceptance are **NOT_PERFORMED** for this change.

The workbench saved and displayed each pilot's optional callsign, but constructed its conversation coordinator from unchanged default personas. Consequently even a saved name reached the model as `callsign: null`. Startup now copies each configured name onto the matching `settings.pilots[].profile`, and mission bindings use the pilot's actor ID to select that profile. Actor IDs, profile IDs and display callsigns remain separate. An unset or whitespace-only preference becomes explicit null; defaults are never mutated. This supplies input context, not proof that generated text follows it.

`conversation.updateCallsigns([{profileId, callsign}])` validates the complete bounded update before changing anything. Actual changes replace only the profile callsign, cancel that profile's bound actors' pending requests and clear their unverified generated histories. The existing coordinator survives: session/request ID history, pawn ownership, revoked generations, clock fault/floor, gates and the occupied generator slot remain intact. An aborted generator that ignores its signal still occupies the single slot until it settles. Same normalized names leave pending work and histories alone.

Before the first settings persistence await, the server invalidates an affected reply/audio job, aborts its work and releases its radio reservation. Affected new conversation requests are temporarily rejected. Names enter the coordinator only after the settings file is successfully replaced. A failed write retains the old saved name and cannot revive cancelled previews. Concurrent settings saves are rejected while one write is pending, preventing shared staging-file and out-of-order identity commits. The existing successful-settings-save disarm remains; human orders, mission state and possession are not reset. Unaffected server conversation work/history is retained unless another existing setting gate cancels it.

The browser conservatively cancels its one playback/fetch immediately when any normalized pilot callsign changes, before waiting for HTTP. This is broader than server cancellation of only the affected speaker. Same-name saves do not cancel playback on that basis. Failed saves leave cancelled playback stopped. This uses the existing playback epoch/abort cleanup, and preserves command-preview epoch handling.

Focused validation: **125/125 PASS MOCK_ONLY** across `server-callsign`, `browser-playback`, `server-conversation`, `server`, `conversation-identity`, `conversation`, and `conversation-review` tests. New cases cover persisted names, crossed actor/profile/name identifiers, unset names, pending text/synthesis/audio reads, failed writes, same-name/unaffected work, held human orders, possession and ignored abort slot retention. One developing test initially assumed possession left the mock armed; it was corrected to check successful-settings disarm separately and compare the actual held-order policy state after possession. No runtime behavior was changed to satisfy that mistaken expectation.

Independent adversarial review is recorded separately in `research/CALLSIGN_SETTINGS_REVIEW.md`. Existing native identity diagnostic receipts and their source hashes remain historical evidence; this correction does not rerun or upgrade those results. No model, adapter prompt, frozen fixture, native receipt, game capability, limit, or paid service is changed.
