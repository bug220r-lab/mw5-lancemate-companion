# Larger-model factual dialogue diagnostic

2026-09-21. This experiment evaluates the already installed Qwen3-4B Q4_K_M candidate after two 1.7B candidates failed factual boundaries. It changes no workbench default and enables no live capability.

An independent worker specified twelve cases in `synthetic/conversation-grounding-cases.json` before inference. Each has required meaning and forbidden claims; answers are reviewed semantically, not scored by matching keywords. Cases cover generated action history, requested fabrication, incomplete mission knowledge, lost visibility, hidden targets, unset callsigns, speaker attribution, instruction text inside observations, conflicting evidence, possibility versus observation, recommendations versus execution and a natural greeting. They are synthetic project observations, not MW5 telemetry fields or user play-style examples.

`scripts/Exercise-ConversationGrounding.mjs --check` validates the cases without starting engines. Importing the script or running it without `--run` is inert. An explicit `--run` creates an exclusive new receipt and reuses the existing pinned local model adapter: one CPU model, four threads, 2,048 context tokens, 64 output tokens, at most 256 characters, nonthinking mode, no prompt cache and stochastic sampling. It uses exactly the current adapter prompt, preserving the hypothesis that model capacity alone might help. There is no prompt tuning against these twelve outputs in this run.

Preflight requires 10 GiB free disk and 5 GiB available RAM. No models or packages are downloaded. Available RAM is sampled every 250 ms; falling below 2 GiB aborts the run and stops the owned worker. Each case has a ten-second diagnostic deadline; timeout stops the run rather than overlapping uncertain native inference with another case. A 233-second work deadline initiates shutdown, with a seven-second cleanup deadline. Unconfirmed termination is reported explicitly rather than counted as success. Interrupt signals request owned-worker shutdown. These watchdogs are bounded attempts, not guarantees against an unresponsive operating system or filesystem.

The receipt records original criteria, actual prompts/outputs, source hashes, runtime verification, elapsed text time, minimum available RAM, incomplete cases and process cleanup. Existing receipts are never overwritten on rerun. Local model identity and runtime hashes are reverified by the existing adapter. Generated text is neither executed nor spoken; no TTS, microphone, game or editor is invoked by the experiment.

Review each response against every relevant required meaning and forbidden claim. A factual contradiction is a failure even if accompanied by a disclaimer. Missing content, truncation and timeout are not passes. Preserve the earlier model failures. One stochastic answer per case cannot prove general reliability, improvement over differently prompted historical runs, first-spoken latency, game-loaded resource acceptance or suitability for live mission dialogue. Any useful result determines the next controlled experiment; it does not automatically select a model.

## Initial resource result and changed configuration

The first run, recorded in `research/QWEN4B_GROUNDING_DIAGNOSTIC.json`, stopped during startup after approximately 9.24 seconds when sampled available RAM reached 1.962 GiB. No response was generated; all twelve cases remain NOT_PERFORMED for that run. Pins were verified, and the owned process stopped. This is a resource-bound failure, not a factual-quality score. Repeating the original command was refused with the receipt hash unchanged.

The version-pinned `llama-server.exe --help` reports default logical batch 2,048 and physical microbatch 512. A separate `--run --compact-batch` attempt selects 128/64 while retaining the same model, 2,048-token context, four CPU threads, prompt, sampling and output cap. It writes `research/QWEN4B_GROUNDING_COMPACT_DIAGNOSTIC.json` exclusively. The adapter's normal launch remains unchanged; the compact option is code-only and not exposed by workbench requests.

Smaller processing batches might lower temporary buffers, while model weights and other storage still need memory. They may also increase prompt-processing time. This is a tested-configuration question, not an assumed optimization. The same 2 GiB guard applies. Since the original run yielded zero outputs, a compact result cannot establish a quality improvement over that run.

The compact attempt also stopped during startup, after 9.21 seconds, with a sampled minimum of 1.468 GiB and no generated answers. Its owned process stopped. The 2 GiB value is a stop threshold, not a guaranteed continuously maintained reserve: allocation can cross it between 250 ms samples. Whole-system memory includes other processes, so the two minima do not isolate a causal effect of batch size.

The pinned binary's help also documents optional weight repacking, enabled by default. A final `--run --compact-no-repack` attempt retains compact batches and adds only `--no-repack`; its separate receipt is `research/QWEN4B_GROUNDING_NOREPACK_DIAGNOSTIC.json`. This might reduce startup allocations at the cost of optimized CPU execution. It does not change model weights, context, sampling, output caps or resource thresholds. Repacking is a code-only boolean; the omitted/true default leaves prior launch arguments unchanged. If this final attempt cannot run within its guards, stop configuration trials and record the remaining semantic cases as NOT_PERFORMED.

The final configuration started in 7.912 seconds, with sampled available RAM never below 2.954 GiB during this run. The first reply then reached its ten-second deadline and was cancelled after approximately 10.011 seconds; no complete answer was returned. That case is FAILED, and the other eleven are NOT_PERFORMED. The run ended after 18.123 seconds with the owned process confirmed stopped. Configuration trials stopped here. None of these attempts establishes a factual-quality result or a usable four-second spoken response; their results do not change the smaller offline audition default. See the independent review in `research/QWEN4B_GROUNDING_REVIEW.md`.

## Same configuration with the editor closed — prepared 2026-09-22

The user subsequently suggested closing the editor to free RAM. The supervising task reports that it closed normally and records the observed application/resource state separately in `research/EDITOR_CLOSE_RESOURCE_2026-09-22.json`. This changed environment justifies one distinct diagnostic using the already tested compact/no-repack configuration; it does not reopen model, prompt or tuning trials.

The bounded command is `scripts/Exercise-ConversationGrounding.mjs --run --compact-no-repack --editor-closed`. The same arguments with `--check` validate the twelve cases and selection without starting a worker or creating a receipt. `--editor-closed` is accepted only in that final position with `--run` or `--check` and `--compact-no-repack`; other combinations are refused. The new run exclusively creates `research/QWEN4B_GROUNDING_EDITOR_CLOSED_DIAGNOSTIC.json`, leaving all three earlier receipts unchanged. A repeated run refuses the existing new receipt before constructing an engine.

The flag records **supervisor-reported environment context**, points to the separate close receipt, and explicitly says `editorStateCheckedByScript: false`. The script does not inspect, close, relaunch or verify the editor. Its `--check` result does not establish current RAM/disk readiness. The supervising task must confirm the preceding worker is stopped and rerun the same resource preflight before starting this diagnostic; no simultaneous model run is authorized by the flag.

All twelve cases, their order/criteria, adapter prompt, model/runtime pins, four CPU threads, 2,048-token context, 64-token/256-character output caps, compact batches 128/64, disabled repacking, no caching, sampling and deadlines remain unchanged. Admission still requires 5 GiB available RAM and 10 GiB free disk; the 2 GiB RAM stop threshold, 250 ms sampling, ten-second case limit, 233-second work budget and seven-second cleanup budget remain in force. The new receipt still requires independent semantic review; a successful editor-closed run would not establish game-loaded performance, first-spoken latency or live companion acceptance. This preparation itself performs no inference.

The supervising task subsequently ran the prepared check and one explicit diagnostic after the recognition worker had stopped. The [editor-closed receipt](../research/QWEN4B_GROUNDING_EDITOR_CLOSED_DIAGNOSTIC.json) records successful admission, **8.455-second startup**, and **2.79 GiB minimum sampled available RAM**. The first case again hit its ten-second deadline after **10.004 seconds**, with no complete output; eleven cases were not performed. Total elapsed time was **18.631 seconds**, and owned-process shutdown was confirmed. The [independent review](../research/QWEN4B_EDITOR_CLOSED_REVIEW.md) covers the actual receipt and its limits. No semantic-quality verdict or four-second spoken-response acceptance resulted, no default was changed, and all prior receipts remain preserved. Do not repeat this unchanged diagnostic or overwrite its exclusive result.

The current adapter also contains the previously reviewed health-response cancellation fixes, so its source hash differs from the older attempt even though the model settings and prompt are unchanged. Together with uncontrolled background load and stochastic sampling, this prevents treating the pair as a controlled estimate of the effect of closing the editor.
