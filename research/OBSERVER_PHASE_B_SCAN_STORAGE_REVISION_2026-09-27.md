## Problem and bounded change

The historical59-test model stopped its component loop when the4096-unit saved-page budget could not admit another complete object/class page pair. Its partial counts were labeled honestly, but a matching probe late in an array of32 or fewer entries could remain unchecked solely because earlier detail paths were long.

The revised algorithm closes detail storage permanently for that attempt and continues only the bounded class checks on captured indices0..31. It still performs one component query, consumes the second F8 attempt before collection, stores pages during that attempt, releases component references afterward and uses only stored pages on later F8 presses. The final-page state saturates; there is no reset, retry or resampling.

For each valid captured component, the source-backed chain is Get Object Class, Is Valid Class, then Get Path Name on the valid class. Validate the class path before exact comparison. The fake model adapter for this chain is a project-local interface, not an invented MW5 function. A separate component object-path read occurs only while detail storage is open. Once storage closes, no more component object paths are requested and no new detail rows or page bodies are formatted/retained; only the current bounded class path and scalar counters are needed. Invalid component/class/class-path entries keep the class scan partial and processing continues to the next bounded slot. Object-path/detail failure alone does not undo a valid class comparison. Fatal adapter errors and EndPlay still terminate the pass without retry; mock exception handling is not a proposed Blueprint exception API.

## Results and bounds

`ClassScanComplete` means the returned count is known and no more than32, and every returned slot was visited and supported a valid bounded class-path comparison. `DetailedOutputComplete` additionally requires all rows retained and all final saved-text checks passed; it does not certify visible display or pixel fit. Overall COMPLETE requires both. A complete class scan with omitted detail pages may report a captured-array match-entry total alongside explicit incomplete details. A partial class scan reports total UNKNOWN and only a qualified checked-subset count. Neither result establishes global observer absence, distinct instance count, probe class resolution, factory-target equality or BeginPlay behavior.

The saved-text/page limits stay4096 UTF-16 units aggregate,1536 summary/context reserve,96 decoration reserve,768 per decorated page,640 summary body,600 other body,40 per path segment,16 logical lines,256 per raw path,128 per level and70 pages. Native pixel fit and glyph coverage remain separate unverified requirements. There is one query, at most32 visited slots/class chains, at most32 object-path reads, and zero component object-path reads after storage closure. Engine query enumeration, returned-array allocation and getter temporaries are outside the display-payload bound. No additional array of omitted paths or class/object references is introduced.
