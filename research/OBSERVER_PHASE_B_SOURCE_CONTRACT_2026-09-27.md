## Proposed state and execution contract

Keep the existing `ControlReadout` type. Add project variables `ControlAttempted: bool=false`, `SnapshotAttempted: bool=false`, `PagesReady: bool=false`, `SnapshotComponents: compatible ActorComponent object-reference array=[]`, `SnapshotPages: String array=[]`, and `PageIndex: int=0`. Snapshot-local counters/strings may be local variables in a new impure project function `CaptureExistingComponentSnapshot`; they are not stock interfaces. Use `ReturnedCount`, `VisitedCount`, `ValidClassChecks`, `ExactMatchEntries`, `RetainedRows`, `InvalidEntries` and explicit count/text/identity failure flags. `InvalidEntries` now counts slots whose component/class/class-path cannot support a valid class comparison; an object-path detail failure does not invalidate an already completed class comparison. Add a sticky capture-local `DetailStorageClosed: bool=false`, plus derived `ClassScanComplete` and `DetailedOutputComplete`. These are project names, not stock APIs. Do not report a match count as a count of distinct objects if duplicate array entries are possible.

On F8 Pressed:

1. If `ControlAttempted` is false, set it true **before** calling anything else, then execute the existing Do Once/Create Widget/Set/Is Valid/Add to Viewport route. Keep Do Once Reset unconnected and Start Closed false. Exit that branch; it must not fall through into snapshot or page logic. No new metadata getter or component lookup belongs on this path. Preserve the exact static marker and existing nonfocusable/non-hit-testable behavior. AddToViewport has no Boolean success output; widget validity does not prove visible display. The user must see and capture the marker before the second press. A synthetic UI.add exception can make the reference model terminal, but there is no source-supported Blueprint try/catch or display-success node to fabricate; the actual graph cannot promise to detect every display failure.
2. Otherwise, if `SnapshotAttempted` is false, set it true first. Validate `ControlReadout`; invalid means stop with no replacement widget and no query. With a valid widget, refuse paused/nonlocal state and an invalid base-class reference, displaying a short explicit `SNAPSHOT NOT COLLECTED: <reason>` through the existing setter. This attempt stays consumed; a later press cannot repair or retry it.
3. If those guards pass, store the controller object path, class path, level, locality and chosen base-class path once. Require nonempty, bounded identity strings and the exact expected base-class path. A failed controller identity bound produces an explicit NOT_COLLECTED result and no component query.
4. Connect **one** `K2_GetComponentsByClass(Self, stock base class)` pure result to **one Set SnapshotComponents value input**. That setter is its sole execution-dependent consumer. Never wire the pure result separately into Length, a loop, formatting or later F8 paths; doing so can reevaluate a pure query. Read `SnapshotComponents` to store `ReturnedCount` once.
5. Run `ForLoopWithBreak` with literal First Index 0 and Last Index31. Before every Get, test `Index < ReturnedCount`; otherwise Break. For each visited slot, increment VisitedCount and validate the component. For a valid component, store its class once, validate that class, then store and validate its nonempty class-path string with the256-unit bound. Compare that raw class path to the exact literal and update ValidClassChecks/ExactMatchEntries. Do these class checks even when DetailStorageClosed is true. An invalid component/class/class-path increments InvalidEntries, makes ClassScanComplete false and continues to the next slot; it never counts as a valid nonmatch. While detail storage is open, retain an index-tagged invalid singleton if it fits. The array is neither sorted nor mutated, and no component function is invoked.
6. Only while DetailStorageClosed is false may a class-valid entry request its object path, validate that path, format its object/class page pair and attempt atomic admission under the bounds below. An invalid/overlong object path or any detail page/budget failure marks detailed output incomplete and sets DetailStorageClosed true permanently for this attempt. A rejected invalid singleton also closes detail storage. Continue the bounded class scan after closure, but perform no more component object-path reads, path segmentation, row formatting or row retention. Keep only each current bounded class-path string long enough to compare it; do not accumulate omitted class/object paths or extra object/class references. ReturnedCount>32 still makes the class scan incomplete even if all first32 validate. Fatal read failures or teardown stop; this does not propose unsupported Blueprint exception nodes.
7. Build all summary and row pages from the stored scalar/string records **during this same capture function**, validate every final page and aggregate bound, set PageIndex=0, set PagesReady=true only after successful construction, and call `SetSnapshot(ToText(SnapshotPages[0]))` once. Page creation uses no additional native component query or object/class/path read. Clear SnapshotComponents after the strings/counters have been frozen, releasing those references; this does not destroy any components.
8. On later F8, only if PagesReady and ControlReadout are valid, compute candidate PageIndex+1 and check it is strictly below stored Array Length. Advance and display that stored string. Otherwise do nothing. There is no modulo, wrapping, reset or recapture; final-page state saturates. Displayed pages must never recompute a live field.

EndPlay removes only the retained widget, clears its reference and any stored component/page arrays, sets PagesReady false, and reaches the existing parent EndPlay call once with the original reason. Do not reset either attempt Boolean or Do Once before teardown; a newly created controller receives defaults naturally. This contract makes no claim about controller reuse across every map transition.

## Output bounds and completeness

The old proposal's “32 entries and 16 KiB” must not be implemented as `Len <= 16384`: the installed declaration counts characters. The selected revised contract is **at most 4096 UTF-16 code units across all saved display pages**, **640 units for the summary body, 600 for context/component bodies**, **at most 768 units per complete decorated page**, **40 units per displayed path segment**, **16 visible lines per page**, **32 visited component slots**, and **70 saved pages maximum**. Page0 is the sole summary; up to three context pages follow, then up to two pages per retained valid component. A component's object and class pages are one atomic retained row. There is no repeated full summary on every page. Every final header, newline, continuation marker, counter and footer participates in both the per-page and aggregate limits. No claim of fit follows from character count alone.

Reserve **1536 units for summary/context pages together** before accepting component rows. Reserve **96 units for every page's final header/footer**, including all separator newlines; allow at most600 for context/component bodies and640 for the summary body; compute the actual decorated length before storing the page. With the fixed header/status/footer vocabulary and page cap70, the maximum decoration is91 units. Check every page-count/status combination in the reference tests and retain the final actual-length checks independently of that reserve. An overlarge controller context detected before the query produces `SNAPSHOT NOT COLLECTED: SUMMARY_CONTEXT_LIMIT`; an unexpected summary/context overflow after collection produces `SNAPSHOT INCOMPLETE: SUMMARY_LIMIT`. Neither may masquerade as an empty or complete result. Each controller/component object path and class path is limited to256 units; level is limited to128. Check those bounds and nonempty/valid identity before combining strings. The fixed stock base path is separately included in the context budget. A component class-path failure invalidates that slot's comparison and continues the bounded scan; a component object-path/detail bound failure closes further detail collection but allows remaining class checks. A controller context failure remains terminal before the query. No full path may be replaced by an ellipsis and still counted complete.

Wrap each retained full path into successive segments of at most40 UTF-16 units, without discarding characters. Use the observed StringLibrary GetSubstring declaration (API215457 onward) for presentation only; compare and retain the original path string separately. The adjacent `GetCharacterAsNumber` declaration at215472 can support checking a proposed chunk boundary. If it would split a UTF-16 surrogate pair, end the current segment one unit earlier. A256-unit path therefore needs at most seven segments. Put the field label on its own line, followed by the consecutive raw path segments, so a reviewer can reconstruct the original by joining only those segment lines without the presentation newlines. Never normalize, lowercase or shorten a path before matching. If actual engine indexing/character-number semantics do not support this exact boundary rule, stop authoring and retain that limitation; do not silently substitute Python code-point slicing as proof of the Blueprint behavior.

The pagebody uses a fixed field order. Page0 shows `SNAPSHOT 1 - NOT LIVE`, final result status, class-scan and detail-output completeness, returned/visited/valid-checked/retained/class-invalid counts, and the explicitly qualified probe match result. Reuse concise summary lines; the two completeness results do not increase the640-unit/16-line limits. Context page1 holds the full Self object path; context page2 holds the full Self class path; context page3 holds the full level/base-class paths and locality. Empty unused context pages may be omitted while preserving all fields. Each retained class-valid component uses two pages: its captured index and full segmented object path, then the same captured index and full segmented class path with match Boolean. Both pages must be admitted together; neither alone constitutes a retained row. An invalid slot uses one explicit invalid-entry page if it fits. A single terse line identifies page x/y, snapshot1 and COMPLETE/INCOMPLETE; a final line says `F8 next saved page; stops at end`. Page totals and status are final before any page is displayed.

Component rows are accepted only after both bounded page bodies, fixed labels and two reserved decorations pass the remaining aggregate budget and page count. Check the whole pair before adding either page or incrementing RetainedRows; an invalid-entry singleton is checked similarly. At most32 entries are processed. The upper bound of70 pages does not guarantee capacity for32 rows: the4096-unit budget or1536-unit summary/context reserve may reject earlier, and that refusal must be explicit. A rejected detail row closes storage; class comparisons continue through the remaining captured indices up to31. The raw returned count remains an observed array length, not an instance guarantee. Visited/checked/retained/class-invalid counts disclose omitted detail rows and invalid comparisons without retaining their full paths.

`ClassScanComplete` requires a known ReturnedCount<=32 and ReturnedCount=VisitedCount=ValidClassChecks: every captured slot supported a bounded valid class-path comparison. `DetailedOutputComplete` additionally requires every returned row retained, no detail/finalization failure, and every saved page passing all limits. Overall `COMPLETE` requires both; omitted or invalid details keep overall `INCOMPLETE`, even if the class scan is complete. If ClassScanComplete is true, the summary may say `Captured array matching entries: K` alongside an explicit incomplete-details result. If false, its headline stays `PROBE MATCH TOTAL UNKNOWN` and any positive result is qualified as matching entries among the valid checked subset. ReturnedCount>32 always means ClassScanComplete=false, with first32 scope, regardless of how many detail pages fit. A known zero is scoped only to this captured base-class array on this Self; it never proves global observer absence, class loading, uniqueness or startup behavior. Human evidence is separately `DISPLAY_CAPTURE_COMPLETE` only when every saved page is visibly captured without clipping or missing lines. Matching entries are not automatically distinct instances.

For valid Unicode, a4096-UTF-16-unit payload needs at most12288 UTF-8 bytes (BMP units need at most3bytes; a valid surrogate pair uses2units/4bytes), conservatively below16KiB. **This is a text-payload bound, not an allocation bound or proof of the collected Len implementation.** The reference model must count UTF-16 units explicitly rather than Python `len`; validate actual engine Len/indexing/Unicode behavior with bounded fixtures before claiming engine-side byte compliance. The engine query itself enumerates actual attachments; the32 ceiling limits subsequent diagnostic processing, not hidden query work, returned-array allocation or temporary native strings. The revised getter ceilings remain32 component validity checks,32 class lookups/class-validity checks/class-path reads, and at most32 component object-path reads; there are zero component object-path reads after DetailStorageClosed. Invalid components skip class reads; invalid classes skip their path reads. Mock class-identity adapters may combine the source-supported class chain, but are project interfaces rather than new MW5 API names. A current bounded class-path temporary is released after comparison, while only admitted detail rows retain raw paths. Clear the captured array and current object/class references at completion or teardown.

The old900x260 TextBlock cannot be presumed sufficient. Proposed Designer candidate:1100x600 at20/20,18-point font, AutoWrapText and confirmed per-character wrapping; each authored page must occupy at most16 readable lines in the actual viewport/DPI. The initial64-unit segments and combined object/class pages were rejected after the [offline font review](OBSERVER_PHASE_B_LAYOUT_REVIEW_2026-09-27.md) found256-unit W/CJK rows expanding from14 logical lines to22 wrapped lines and638–726px high. The revised40-unit segments and separate path pages address that specific candidate overflow. They remain proposals requiring fresh fixture/font review and actual widget verification; unsupported glyphs, fallback fonts and viewport/DPI behavior remain unknown. Logical line counts alone cannot establish the16-visible-line bound. Keep the widget nonfocusable/HitTestInvisible, with no scroll input/cursor/input-mode changes. If a maximum fixture page clips, adjust the layout or lower the admitted page bound before packaging; do not call clipped output complete.
