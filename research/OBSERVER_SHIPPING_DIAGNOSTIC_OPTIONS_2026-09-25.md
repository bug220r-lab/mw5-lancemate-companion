## Ranked decision

1. **Selected PROPOSED control: official substitution + deliberately triggered UMG readout.** One temporary stock override is the price of obtaining an entry path independent of the unproven registration factory. The output must be demonstrated before drawing an absence conclusion. The dedicated input is also a scope addition; it performs no game order and must not replace a native binding.
2. **Deferred: bundled Victory text-file marker.** The installed API at 293146–293160 declares `file_io_save_string_text_to_file(save_directory, joyful_file_name, save_text, allow_over_writing=False, allow_append=False) -> bool`. Its shipping implementation, actual write success and failure behavior are untested. A file writer placed only in the silent component would add another unknown. Do not make it a prerequisite for the morning control.
3. **Not selected: add another mod framework or use a loader.** The [YAML authors' current listing](https://www.nexusmods.com/mechwarrior5mercenaries/mods/459), version 0.98.5.1 updated September 12, 2026, documents an in-game F10 console and file-list exports. This is useful shipping-mod precedent, but it neither identifies this probe's startup route nor proves the bundled Victory call. Installing a gameplay overhaul would change the experiment substantially. No such dependency is proposed.

## Small morning authoring recipe — separate control A

All new identifiers below are **project proposals**, not PGI interfaces. Author manually in a working editor session; unattended authoring remains unproven. If a required node/type is unavailable or compilation fails, record that blocker and stop. Do not rerun the completed controller/mode/reference exports.

1. Create a dedicated temporary mod, proposed name `LanceObserverDiagnosticControl`. In this mod only, use `Save To Mod` for **`/Game/Modes/InstantAction/InstantActionPlayerController`**. Preserve existing functions, construction, inherited behavior and parent calls. Do not edit the stock source asset, mode default, controller base, factory or original observer assets. No BeginPlay override is needed for this control: the deliberate input is its entry point.
2. Create one new `UserWidget`, proposed `WBP_ObserverDiagnosticControl`, with a readable fixed-position TextBlock and generous width. Default text: `CONTROL A — OUTPUT ONLY`. Use `IsFocusable=False` and `HitTestInvisible` for self and children. Add a small impure project function `SetDiagnosticText(Text)` that calls that TextBlock's `SetText`. No input-mode, focus or cursor changes; no live bindings or Tick. This uses the already-authored UMG pattern, with its own independent widget.
3. Add exactly one uniquely named mod input action, proposed `ObserverDiagnosticSnapshot`, using the generated mod input template and its actual documented syntax. Select a key/chord only after checking the user's current native/mod bindings. Do not guess a free key, alter their Input.ini, install Mod Options, or consume an existing native action. The selected binding and consumption setting belong in the reviewed manifest.
4. In the substituted controller, retain one owned widget reference and a small press-state variable. On the action's first **Pressed** event, create this new widget with **OwningPlayer=self**, store it, and call **AddToViewport**, proposed ZOrder 1000. The first execution path must contain **no observer lookup, component-owner cast, registration check or existing observer-widget dependency**. The static marker is the positive control. Record create-invalid as an authoring-visible branch; shipping silence still remains inconclusive.
5. On the second Pressed event, use the retained valid control widget. Require the selected stock `PlayerControllerComponent_C` base-class reference to be valid, then take **one** `GetComponentsByClass` snapshot on **self**. Store the array once, then render controller object/class path, level name, local-controller Boolean, selected base-class path, array count, and every valid returned component's object path and class path (`GetObjectClass` followed by `GetPathName`). Use the base type rather than a hard reference to the probe class; this avoids introducing a new direct loading dependency on the probe. Match the exact `/LanceObserverProbe/BP_LanceObserverProbeComponent.BP_LanceObserverProbeComponent_C` string only when interpreting recorded output. This first control does **not** establish that the exact probe class was successfully loaded if no instance is found.
6. Bound display to 32 entries and 16 KiB; display explicit `TRUNCATED` or `INVALID ENTRY` status instead of claiming a complete list when the bound/validity check fails. These data bounds do not guarantee visible fit. Put controller identity, exact probe-class match count and completeness/truncation status in a visible header; require verified full fit or capture every page before treating the snapshot as complete. The small static Phase A TextBlock is not automatically suitable for enumeration. Values are a snapshot, not continuous telemetry. Ignore further snapshot triggers for that controller. On EndPlay remove only this retained control widget and clear the reference, preserving any inherited EndPlay behavior/parent call. Do not remove all widgets or destroy components.

This first control needs only the substituted controller, one new widget and its input configuration. It does not create an observer, invoke `AddPlayerControllerComponents`, change registration, or touch AI. ## One bounded shipping attempt and interpretation

**Before the attempt:** refresh builds, hashes, DLC/active-mod configuration and process-closed state. Use a named disposable stock Instant Action setup, a mod-off baseline and the exact existing probe package plus this new reviewed control package. Pin screenshots/output locations, all installed files, restore points and the exact temporary input configuration. The coordinator must resolve deployment permission for this concrete stock override and input addition; this research does not grant it.

After the normal mission HUD is visible and the game is unpaused, the user presses the selected key once. Allow ten seconds for the static marker. **No marker: stop this attempt.** Record `CONTROL_OUTPUT_NOT_ESTABLISHED`; do not diagnose the observer, change activation, call the factory, try successive ZOrders or install logging tools during that attempt.

If the static marker appears, capture it, then press once more and capture the complete snapshot. The two-state sequence distinguishes actual action/readout progress from an unchanged Designer default. Stop immediately for input interference, crash, unexpected behavior, duplicate control widgets, invalid/truncated output or a nonlocal/unexpected controller/world.

| Recorded outcome | Warranted conclusion |
|---|---|

| Complete snapshot identifies the intended local controller and lists the exact probe class | A probe instance exists on that controller at that moment despite the absent original overlay. Investigate its BeginPlay/owner/UI stages next; do not claim which stage failed yet. |

| Unexpected controller/class/level, nonlocal controller, invalid entries or truncation | The diagnostic lacks the intended complete observation. No absence conclusion. |
