# MW5 Lancemate Companion: work completed to September 23, 2026

**Snapshot:** September 23, 2026; local branch `codex/companion-foundation`, commit `9028c566977a834c1c9a079a23020bc58b1bcd96`. This report covers the dedicated project record beginning September 20. The first Git checkpoint was made September 21, so the earliest milestones are reconstructed from dated project records. This is a review of existing evidence, not a new editor, game, model or gameplay run.

## Executive summary

The project has moved from feasibility research to a substantial **offline companion prototype**. It has a source-backed map of MW5's lance orders and AI behavior, a three-lancemate tactical recommendation policy, conservative observation and human-command arbitration, a local browser workbench, local text/speech/recognition components, synthetic evaluations, a reproducible offline package, and a private source backup. The latest recorded companion suite passed **1,230/1,230 tests, classified MOCK_ONLY**; this review independently rechecked all 116 file hashes named by that receipt, with no mismatch. Separate editor exports and local CPU trials provide their own, narrower evidence.

The **full mod is not complete**. There is no built/cooked/installed passive observer, shipping-game adapter, accepted in-game order, live three-lancemate coordination, or direct piloting. No gameplay improvement or release performance target has been established. The next dependency is an actual, measurable observer creation probe: supported executable asset authoring and readout, exact package/manifest, then an isolated Instant Action test. [Current checkpoint](OVERNIGHT_CHECKPOINT_2026-09-23.md) · [full delivery contract](../design/FULL_MOD_DELIVERY.md) · [latest validation receipt](COMPANION_VALIDATION.json)

In this report, **OBSERVED** means a named local file, editor export, browser interaction or component trial was actually inspected; **DOCUMENTED** means a source or declaration states a contract; **PROPOSED** means a design or test plan; **MOCK_ONLY** means synthetic execution; **UNKNOWN/BLOCKED** and **NOT_PERFORMED** retain their literal meanings. An editor result is not a shipping-game result. A posted order is not proof of native acceptance, and native acceptance would not by itself prove movement.

### Native lance orders and AI behavior

The exported Form On Me graph constructs a configured `FollowOrder`, recipient/context data and a local controller posting path. The dispatcher derives recipients from selected member display objects. FollowOrder and SquadOrderBase expose job creation and posting behavior. The UI completion callback is only UI completion. The reports distinguish order submission from native assignment, movement and completion; the current-AI binding, scheduling, manual-order provenance and live readback still need evidence. The FollowJob source also shows that worker setup reacquires the player-squad leader, so an earlier issuer pawn cannot simply be assumed to remain the follow target. [Graph review](BLUEPRINT_EXPORT_REVIEW_2026-09-20.md) · [order lifecycle](ORDER_LIFECYCLE_TRACE.md) · [readiness synthesis](../design/TACTICAL_CONTROL_READINESS.md)

The broad collection processed **249/249 inventoried entries** with zero recorded collection/audit mismatches. It produced **244 source texts** and **128 class-default texts**, about **56.53 MiB** including the generated API reference. The semantic ledger accounts for **167 semantic reviews, 77 supporting-data reviews and five unavailable entries**, with hashes and source ranges. Analysis covers assignment/configuration, order and job lifecycle, combat, movement, other units and tactical state. It identifies specific behavior-tree branches, follow/combat interaction, target-selection and role/configuration leads, while retaining native algorithms, runtime state and the five export gaps as unknown. [Collection receipt](AI_COLLECTION_RESULT_2026-09-20.md) · [coverage ledger](AI_COVERAGE_LEDGER.md) · [technical appendix](AI_TECHNICAL_APPENDIX.md)

In particular, a connected dropship helper writes the whole movement-input structure, and the documented pawn `stop_logic` call is not reversed by `resume_logic`. These findings prevent a guessed takeover sequence; they do not establish exclusive movement/aim/fire ownership, safe restoration or an executable direct pilot. ## Offline prototype and user experience completed

The tactical prototype is a pure function over explicit snapshot and prior state. It can recommend focus, supplied-position movement, safer regroup or retaining native behavior for up to three actors. It requires current actor bindings, visibility and route/occupancy evidence; it never invents a hidden target or viable path. Human orders persist conservatively, including when their completion/persistence is unknown, and all recommendations are non-dispatchable. Its six evidence-linked playbook rules are revision aids, not model training or verified tactics. The initial **48 scenarios + three properties** and separate **31/31 adversarial cases** passed MOCK_ONLY. A later bounded 2,950-call timing sample measured 0.0225 ms p95 on tiny synthetic snapshots, excluding all game observation and transport costs. [Policy contract](../design/OFFLINE_TACTICAL_PROTOTYPE.md) · [results](OFFLINE_TACTICAL_RESULTS.json) · [independent review](TACTICAL_INDEPENDENT_REVIEW.md) · [timing](TACTICAL_POLICY_TIMING.md)

The local workbench implements synthetic observation validation, actor/controller/pawn history, explicit human possession and order holds, three-recipient arbitration, expiry/deduplication, and separate submission/assignment/behavior evidence stages. The browser UI presents three personas, mission-scoped radio, command/parser previews, settings/callsigns and explicit local text/voice controls. A push-to-talk path provides a transcription **preview**. Generated text and mission facts remain unverified; neither the parser nor microphone preview dispatches an MW5 command. Saved preferences persist, while mission state is reset. Independent reviews repaired concrete defects involving stale identity, retained human intent, radio ownership, async playback, shutdown and settings changes. [Implementation checkpoint](IMPLEMENTATION_STATUS.md) · [workbench](../companion/README.md) · [browser preview](WORKBENCH_BROWSER_VALIDATION_2026-09-22.json)

Experience work also produced an edgy female pilot draft, two complementary pilot roles, mission rehearsal, personality and callsign comparisons, static radio lines and a branch-aware memory/command contract. The early command and memory exercises were synthetic: the memory replay met **92 expectations across 12 cases**, plus **14 adversarial checks**; **16 static radio candidates** met their fixture criteria. These documents and checks do not create campaign memory or in-mission speech. Callsigns remain user-unset.
