**OBSERVED** in [010 source](evidence/editor-source/ai-research-collection-20260921T030437Z-f7d8e930/010-MW5PlayerController-source.COPY), graph `AddPlayerControllerComponents`, lines **1444–1775**:

The cast-failure output has no linked continuation in the body.
4. A true `bAddAtRuntime` is required (**1613–1621**, **1706–1714**). A class already in the just-cleared/then-populated `RuntimeControllerComponents` array is skipped (**1466–1476**, **1604–1612**, **1698–1705**).
5. Otherwise `ActorComponent` supplies `MWBlueprintUtils.AddComponentByClass` via the conversion/reroute chain. `InActor` is **self**, `Reason` has no supplied value, and the returned component reference is unconnected (**1489–1501**, **1570–1576**, **1622–1642**, **1715–1723**). The following `Array_Add` records the requested class; no success check on the returned component gates this record (**1477–1488**).
6. On registry-loop completion, the graph enumerates components of the base component class on **`GetLocalController`**, then calls each one's `ControllerConfigured`. The passed `Controller` is **self** and the pawn arguments are self's stored `InOldPawn`/`InNewPawn` variables (**1536–1568**, **1656–1697**).

That last distinction matters: the add target is self, while the configuration enumeration target is the local controller. **PROPOSED requirement:** any future explicit caller must establish that these refer to the intended same controller and must establish pawn-field freshness. The factory itself is not evidence of those preconditions. The stored pawn fields default to `None` (010 defaults **67–68**); their only `VariableReference` occurrences without a function scope in this source are the factory getters (**1683**, **1691**). The ordinary `OnPawnChanged` path below instead passes its function inputs. Native or external writes to the stored fields remain unverified.

## Duplicate and lifecycle obligations

**OBSERVED:** clearing a list of class references is not destruction of existing actor components. The factory's `Contains` check consults only that list; it does not enumerate already attached components before creation. The graph does not establish idempotence over repeated calls or prevent overlap with a component already attached by some other route. Native `AddComponentByClass` might impose additional behavior, but its implementation is unavailable here. Recording a class after an unchecked call also does not prove successful creation. Therefore the probe must count actual instances, not requested classes or configuration callbacks.

**OBSERVED:** [238 source](evidence/editor-source/ai-research-collection-20260921T030437Z-f7d8e930/238-PlayerControllerComponent-source.COPY), **20–64**, exposes `ControllerConfigured(Controller, OldPawn, NewPawn)` with no connected body, plus disabled BeginPlay/Tick nodes. [238 defaults](evidence/editor-source/ai-research-collection-20260921T030437Z-f7d8e930/238-PlayerControllerComponent-defaults.COPY), **2–9**, shows `bCanEverTick=False`, `bAutoActivate=False`, `bReplicates=False` and `bIsEditorOnly=False`. These are base defaults, not a guarantee that a new subclass will initialize, tick, cook or replicate. A passive implementation needs explicit, reviewed initialization and cleanup behavior.

**OBSERVED possession lead:** native event `HandlePawnPossessionChanged` forwards the old/new inputs to `OnPawnChanged` (**010:3575–3586**, **2844–2854**). `OnPawnChanged` has an independent local-controller branch and calls `OnInputTypeChanged`, `HandleLivingActorBindings`, then `HandleMechBindings` (**6580–6649**, **6674–6698**, **6747–6760**). `HandleMechBindings` compares old/new references (**4796–4806**, **4981–5014**), manages old/new mech delegates and calls component `ControllerConfigured` on the matching branches (**4722–5426**; calls at **4783–4795** and **4828–4840**).

**Observed limitations:** the invalid-new-pawn output is unconnected (**5050–5059**). The spectator fallback's branch uses `IsMultiplayerClient`, with its true output unconnected (**4851–4860**, **4997–5005**). An unchanged old/new reference exits its branch (**5006–5014**). Thus this callback path alone cannot promise all null/unpossessed/world-transition notifications. It is configuration of existing components, not a demonstrated creation path.

**PROPOSED requirements:** invalidate retained identity on an independently proven lifecycle event or the next bounded sample; re-resolve controller/pawn reciprocity every sample; present unknown state directly; track owner/world/instance identity separately from `ControllerConfigured` callback count; stop timers and release observer references on teardown. None of these observer behaviors has been implemented or measured here.
