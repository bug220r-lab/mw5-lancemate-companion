## Dormant capture helper

New files: `scripts/Capture-BlueprintClipboard.py` and `scripts/Test-Capture-BlueprintClipboard.py`. The helper imports no Unreal module and contains no clipboard setter, paste, keyboard/mouse input, asset save/compile or launch operation. Its Windows calls only inspect/lock/read/release clipboard data. It imports the exact SHA-matching WindowBridge source bytes solely to reuse its foreground/executable/window/receipt/pixel guards. Importing WindowBridge is not a native UI action; its Desktop object is created only by explicit helper capture invocation.

The command contract is:

```text
python -B scripts/Capture-BlueprintClipboard.py
  --receipt <fresh WindowBridge receipt.json after the observed Copy>
  --image-sha256 <that reviewed client.png SHA256>
  --bridge-sha256 <independently reviewed current scripts/WindowBridge.py SHA256>
  --attempt-id <new unique lowercase ID, 8–80 letters/digits/hyphens>
  [--review-region <left> <top> <right> <bottom>]
```

This is a template, not an executable prepared native entry. The capture must bind a normal window whose current title contains `BP_CodexAuthoringProbe`; popup/foreground-child bindings are refused. If the actual editor layout does not provide that identity, stop and review an explicit alternative binding instead of weakening the check implicitly. By default every pixel of the full image must match. Normal WindowBridge executable/process/focus guards and the120-second capture lifetime apply.

**Narrow exact-region revision:** the coordinator's first capture attempt stopped before clipboard access because an animated green tutorial halo in the editor's top chrome changed the whole image. The optional explicit region now reuses WindowBridge's existing exact region comparison with wait0: four integer image-relative coordinates, within the actual image dimensions, positive extent and at least10000 pixels. There is no per-pixel mask, tolerance, automatic wait, input or clipboard write. For the currently reviewed1258×686 client, the coordinator identified graph rectangle `195 135 940 680`; this is an invocation choice to recheck against each fresh screenshot, not a baked-in default. The full reviewed image file/hash/dimensions and receipt remain pinned and are rechecked before and after the single clipboard read; process/title/focus, source/backup and bridge identity checks still run on both sides. Both exact pixel results and the chosen region are recorded. After the second guard, the clipboard sequence must still equal the sequence surrounding the original read; drift refuses persistence without reading a replacement payload. The full screenshot remains evidence of the title/chrome while only the explicitly reviewed rectangle participates in visual equality.

On success, a new `research/evidence/blueprint-clipboard/<attempt-id>/` contains the exact copied text encoded as UTF-8 (`native-print-string.clipboard.txt`) and `capture.json` with its length/hash, the reviewed capture pin, editor identity, clipboard sequence, source/backup pins and explicit limitations. The original Unicode string is not normalized; line endings remain in the saved UTF-8 text. The helper never prints raw clipboard contents. Its envelope validator does not validate every Blueprint pin/property or execute/import any payload, and does not claim clipboard origin without the separate UI Copy receipt.
