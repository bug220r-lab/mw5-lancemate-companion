# Direct-pilot firing ownership: bounded source delta

Reviewed 2026-09-22. **OBSERVED:** preserved editor declarations and selected connected Blueprint pins. **DOCUMENTED:** signatures and descriptions below. **UNKNOWN/BLOCKED:** exclusive firing/aim ownership and restoration. **Runtime, editor execution, reflection import, game writes and direct-piloting tests: NOT_PERFORMED.** This report adds a narrow source lead; it does not advance M6 through its ownership gate.

The useful new lead is `AIWeaponControlSystemComponent.suppress_firing`, an exposed read/write Boolean. Its documentation does **not** establish whether it stops ongoing fire, prevents only new native decisions, or permits a separate trigger writer. Those distinctions must be resolved before combining it with the separately declared weapon-trigger functions.

## Exact open question and minimum future experiment

**UNKNOWN/BLOCKED:** Does a live AI controller's `suppress_firing=true` stop only new native trigger requests, also cancel an existing firing sequence, or block the underlying weapon trigger regardless of its caller? Can another native system overwrite it? What state must be preserved/restored so that the same AI resumes firing without a stuck trigger, stale target or control leakage through a possession change? A Boolean without an ownership protocol cannot answer these questions. Aim authority remains a separate unresolved requirement.

**PROPOSED, NOT_PERFORMED:** after a working observer and a reviewed, manifest-listed game-thread probe exist, use one designated AI and one untouched sentinel in disposable stock Instant Action. Record the exact build, actor/controller/pawn/component bindings, loadout and baseline native firing. Start with a simple single weapon and visible target. Observe candidate fire/sequence/result events and independently visible firing, with ammunition/heat changes where applicable. Record rather than assume the initial suppression value.

First test **suppression and restoration only**: apply the candidate flag to the designated component, measure whether a current sequence finishes and whether new sequences begin, then restore the captured value only while the same ownership/binding remains verified and no conflicting writer is detected. Compare the sentinel and a fresh baseline. Do not add manual trigger writes in this trial; those would confound suppression with trigger behavior. A later separately bounded single-trigger trial would ask whether low-level firing can coexist with proven native suppression and then stop/restore correctly.

The actual probe manifest, disposable scenario configuration, time limit, stop conditions and rollback must be complete before deployment. Stop for wrong-recipient effects, possession, stale identity, world change, unknown authority or unconfirmed cleanup. A stale component must not receive a blind “restore false” write. If restoration cannot be safely confirmed, terminate the disposable test and use the prepared removal/restart rollback; do not claim watchdog recovery. No such probe was built or deployed here, and this proposal does not bypass the earlier integration gates.
